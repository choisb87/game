# VALIDATION

검증일: 2026-03-17 (비주얼/입력 보강 반영)

## 환경 제약

- 이 작업 환경에는 `godot`, `godot4`, `flatpak run org.godotengine.Godot` 실행 파일이 설치되어 있지 않았습니다.
- 따라서 실제 에디터 실행, 런타임 플레이, Android export 검증은 수행하지 못했습니다.

## 1차 검증 (초기 생성)

1. 파일 구조 생성 확인
   - `project.godot`, `scenes/`, `scripts/`, `assets/`, 문서 파일이 모두 생성되었는지 확인했습니다.

2. 프로젝트 참조 무결성 점검
   - `project.godot`의 메인 씬이 `res://scenes/Main.tscn`을 가리키는지 확인했습니다.
   - 각 `.tscn`의 `ext_resource`가 실제 스크립트 파일을 가리키는지 수동 점검했습니다.

3. 텍스트 기반 GDScript 점검
   - 딕셔너리 내부 `Vector2` 필드 직접 수정처럼 문제 가능성이 높은 코드를 수정했습니다.
   - 체력바 비율 계산을 위해 적 데이터에 `max_hp` 필드를 보완했습니다.

4. 메타데이터 및 에셋 형식 확인
   - `metadata.json`, `app_icon.svg` 문법 확인 완료.

## 2차 리뷰 — 게임플레이 품질 검토

### 검토 관점
- 게임플레이 명확성 (Gameplay Clarity)

- 첫 1분 재미 (First-Minute Fun)
- 명백한 약점 (Obvious Weak Spots)

### 발견 및 적용한 수정사항

| # | 문제 | 심각도 | 적용한 수정 |
|---|------|--------|------------|
| 1 | **피격 후 무적 시간 없음** — 연속 탄환이 동시에 맞으면 즉사 가능. 상업용 슈터 기본 기능 부재 | 높음 | 피격 시 0.6초 무적 프레임 + 깜빡임 시각 피드백 추가 |
| 2 | **콤보 유지 불가** — 0.48초 감소 간격이 초반 적 밀도 대비 너무 가혹. 캐주얼 플레이어가 멀티플라이어를 경험하기 어려움 | 높음 | 감소 간격 0.48초 → 0.72초로 완화 |
| 3 | **적 격파 시 점수 팝업 없음** — 킬 보상의 시각 피드백 부재. 상업 슈터 필수 요소 | 중간 | `score_popups` 시스템 추가: 적 격파 위치에 "+점수 x배율" 텍스트가 떠올라 사라짐 |
| 4 | **사망 연출 없음** — 실드 0 시 게임이 그냥 끝남. 카타르시스 부재 | 중간 | 사망/실패 시 대형 폭발 파티클(36개) + 충격파 + 화면 흔들림 + 플래시 추가 |
| 5 | **초기 충전량 24%** — 첫 오버드라이브까지 너무 멀어 핵심 메카닉 체험 지연 | 중간 | 초기 충전 24% → 38%로 상향. 첫 플레이에서 오버드라이브를 더 빨리 경험 |
| 6 | **픽업 자석 범위 좁음** — 240px 흡인 범위, 플레이 쾌적성 저하 | 낮음 | 자석 범위 240px → 320px로 확대 |
| 7 | **스폰 직후 무방비** — 게임 시작 시 무적 시간 없어 즉시 피격 가능 | 낮음 | 게임 시작 시 1.2초 무적 부여 |
| 8 | **사망 후 플레이어 기체 계속 표시** — alive=false 이후에도 기체가 그려짐 | 낮음 | `_draw_player()`에 alive 체크 추가 |

### 수정하지 않은 항목 (런타임 검증 필요)

| 문제 | 이유 |
|------|------|
| **사운드 완전 부재** — 효과음·BGM 없음 | 오디오 파일과 AudioStreamPlayer 추가 필요. 프로시저럴 오디오는 복잡도 높아 런타임 테스트 없이 안전하지 않음 |
| **HUD 정보 과밀** — 45초 아케이드에 콤보·실드바·충전바·상태 텍스트가 동시 표시 | UI 레이아웃 변경은 .tscn 구조에 영향. 에디터 확인 후 조정 권장 |
| **터치 영역과 플레이 영역 분리** — control_rect이 화면 하단 34%만 커버, 상단 터치 시 Y축 감쇠 적용 | 의도적 설계일 수 있어 변경 보류. 실제 플레이 테스트 후 판단 필요 |
| **랭크 임계값 밸런스** — S 5200, A 4000, B 2800, C 1600 | 실제 플레이 통계 없이 조정하면 역효과. 3~5회 플레이 데이터 기반 조정 권장 |

## 코드 품질 확인

- 모든 변경은 기존 코드 패턴(Dictionary 기반 엔티티, signal 기반 통신)을 따름
- 새로운 외부 의존성 없음
- `_draw_score_popups()`는 `ThemeDB.fallback_font` 사용 — 커스텀 폰트 불필요
- `invincible_timer`는 `_physics_process`에서 감소, `_apply_player_hit`에서 체크 — 경쟁 조건 없음

## 3차 보강 (2026-03-17)

- 전투 플레이 영역을 확대하고 드래그 제어 구간을 더 위까지 끌어올려 한 손 플레이 추적성을 개선했습니다.
- HUD 패널, 메뉴 카드, 결과 카드에 그림자/보더/라운드 스타일을 추가해 기본 Godot 느낌을 줄였습니다.
- 플레이필드에 다중 프레임, 헤일로, 창문 발광, 총알 후광, 픽업 글로우를 추가해 화면 밀도를 올렸습니다.
- 드래그 존을 과하게 거슬리지 않는 약한 오버레이로 바꿔 입력 가능 영역을 더 명확히 했습니다.

## 남은 리스크

- 실제 Godot 4.2 에디터에서 열었을 때 UI 레이아웃 미세 조정이 필요할 수 있습니다.
- `draw_string()` API가 Godot 4.2에서 정상 동작하는지 런타임 확인 필요 (4.x에서 시그니처 변경 이력 있음).
- 드로잉 기반 연출은 모바일 실기기에서 색감과 대비를 추가 조정할 가능성이 있습니다.
- 사운드 미탑재로 인해 상업적 완성도에 가장 큰 갭이 남아 있습니다.
